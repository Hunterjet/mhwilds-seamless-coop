## 4. Design implications (first pass)

1. **Vanilla already has most of the plumbing**: link-party *sync* (auto-bring members into the leader's quest),
   late-join snapshot sync, NPC network authority, and scene-transition sync barriers. The story gate looks like an
   explicit *policy* (`PARTY_SYNC_OPTION.LEAVE_StoryEvent`, story FSM `DRAWOFF_REPLICA_PLAYER`, join checks), not a missing
   capability. ⇒ The cheapest viable approach is to **relax policy checks for modded link-party members** and then fix
   whatever desyncs appear, rather than building new replication.
2. **Story FSMs run locally per player** (same lesson as MHW 1.2) — mirroring cutscenes/flags must be designed carefully
   (host-authoritative triggers, client-side "play cutscene X" via the normal event path or the gallery path).
3. **Progress comparison is possible** via story package flags/mission IDs; use it to block joins that would skip a
   player's story (MHW users hard-locked saves this way) unless the joiner opts into "spectator" mode.
4. A side-channel for mod-to-mod messages is needed (Lua has no sockets). Candidates: Steam P2P in a small C++
   REFramework plugin (Steam IDs from the member list's platform info), or the game's own session send/chat path.
